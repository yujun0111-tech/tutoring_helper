# 과외 수업교재 제작 도구 · v5

`index.html` 하나로 실행하는 교재 편집기입니다. PDF 렌더러, 문제 번호 OCR, 언어 모델과 글꼴 리소스를 파일 안에 포함합니다. 실행 중 파일을 외부 서버에 업로드하거나 CDN에서 추가 리소스를 받지 않습니다. 파일 크기는 약 10MB입니다.

## GitHub에서 열기

GitHub Pages를 활성화하면 다음 주소에서 실행합니다:

https://yujun0111-tech.github.io/tutoring_helper/

저장소의 **Settings → Pages → Build and deployment**에서 **Deploy from a branch**, **main**, **/(root)**를 선택하고 **Save**를 누릅니다. `.nojekyll`과 루트의 `index.html`을 그대로 정적 사이트로 게시합니다. 별도 빌드나 서버 설정은 없습니다. Pages가 활성화되기 전에는 위 실행 주소가 열리지 않습니다.

앱 파일을 GitHub에서 받으려면 저장소의 **Code → Download ZIP**을 사용하고, 압축을 푼 폴더의 `index.html`을 Chrome 또는 Edge로 여세요.

## 실행과 사용

1. HTML 파일을 Chrome 또는 Edge에서 엽니다. 우클릭 → **연결 프로그램**으로 브라우저를 선택할 수 있습니다.
2. 화면 상단의 **새 탭으로 열기**는 현재 작업을 새 탭으로 복사합니다. 차단되면 **앱 HTML 저장**으로 작업을 포함한 HTML을 저장해 브라우저에서 여세요.
3. 원본 PDF 또는 페이지 이미지를 선택하고 `1-21`, `1-20, 25-30`처럼 범위를 지정합니다. 기존 12쪽 제한은 없으며 순차 처리합니다.
4. **자동 추출하기**를 누르면 문제 번호별로 조각을 만들고 선택합니다. 선택 목록의 **유형별 대표 1 + 적용 1** 버튼은 필요한 경우 따로 사용할 수 있습니다.
5. **PDF 내려받기**는 미리보기와 별개로 300 DPI A4 PDF를 만듭니다. **작업 저장**은 편집용 JSON을 만듭니다.

## v5에서 실제 교재로 수정·검증한 부분

제공된 160쪽 PDF에서 A스텝과 간지 페이지를 제외한 **126쪽, B·C스텝 812문제**를 검사합니다. 각 단원의 시작·끝 번호를 원본에서 따로 확인한 기대값과 비교하여 누락·중복·순서 오류를 검사하며, 같은 열의 자르기 범위가 겹치지 않는지도 확인합니다.

- 분석용 축소 이미지에서는 위치만 찾고, OCR은 원본 해상도에서 수행합니다. 주황 배지의 흰 숫자에는 별도의 대비와 자르기 폭을 적용합니다. OCR 결과가 다르면 이웃 번호와 일치하는 **실제로 읽힌 후보**만 선택합니다. 번호를 임의로 채우지는 않습니다.
- 녹색 유형 배지와 난이도 표시를 문제 번호와 구분합니다. 파란 번호 위의 빨간 필기는 다른 색으로 분리해 읽고, 다음 문제의 표시가 더 높게 시작하는 경우 그 부분까지 이전 문제에서 제외합니다.
- 기울어진 가운데 구분선 때문에 한 단으로 판단되는 페이지는 양쪽의 실제 번호 위치로 두 단을 다시 확인합니다. 노랑·주황·연두색 바깥 장 표시와 쪽번호를 자르기에서 제외합니다.
- 스캔된 세로 구분선의 흔들림이 풀이 공간을 아래로 밀지 않도록 본문 정렬 위치도 경계 계산에 사용합니다. 원본 이미지의 본문 픽셀은 수정하지 않습니다.
- 페이지 렌더링 후 PDF.js 이미지 캐시를 정리합니다. HTML 캔버스가 백그라운드 탭의 PNG 저장을 오래 지연하는 브라우저에서는 OffscreenCanvas로 저장합니다.

## 기존 처리 방식

- PDF.js로 PDF를 그립니다. 텍스트, 이미지 마스크·투명도, 선과 점선 등 PDF 그리기 명령을 처리합니다. 이전의 제한된 자체 PDF 해석기는 제거했습니다.
- 숫자가 네 개의 연결 요소인지 추측하던 코드를 제거했습니다. PDF의 텍스트 좌표 또는 Tesseract의 숫자 OCR로 번호와 위치를 읽습니다. 붙은 숫자, 녹색·파란색·붉은색 번호, 흰 숫자가 있는 주황색 배지를 처리합니다. OCR은 문제 내용을 이해하거나 난이도를 판단하는 기능이 아닙니다.
- **문제 번호가 있는 조각을 개념으로 확대하지 않습니다.** 진짜 개념 본문만 넓은 행을 사용할 수 있습니다. 읽기 어려운 번호는 목록에 **번호 확인 필요**로 표시합니다.
- 한 조각에 여러 번호가 있으면 다시 나눕니다. 예전 작업 JSON에서 한 이미지로 저장된 69·70, 78·79, 113·114·115 같은 묶음도 불러올 때 재검사합니다. 새 작업 형식은 `folio-lesson-v3`이며 v1·v2 파일도 읽습니다.
- 문제는 2열 × 2행, 페이지당 최대 4개입니다. 긴 문제는 한 열 전체를 사용하고 반대쪽에 일반 문제 두 개를 넣어 3문제가 됩니다. 번호가 두 개 이상 남은 조각은 그대로 배치하지 않도록 검사합니다.
- **본문의 회색 픽셀을 지우는 보정을 없앴습니다.** 보기 박스, 분수선, 그래프 및 글자 가장자리 값을 그대로 보존합니다. 페이지 여백선은 자르기 경계에서 제외하며, 실제 보기 박스의 테두리는 유지합니다.
- 유형 제목은 다음 영역의 시작 경계로 취급하여 이전 문제에 섞지 않습니다. 본문 없는 개념 제목만으로 빈 페이지를 만들지 않습니다. 바깥의 노란 장 표시도 문제에 포함하지 않습니다.
- 자르기 여백은 다음 번호의 경계를 넘지 않습니다. 원본 열 너비에 맞춰 배율을 정하므로 폭이 짧은 문제를 과도하게 확대하지 않습니다.
- 확대율·화면 픽셀 밀도에 맞춰 미리보기를 다시 그립니다. 렌더 배율은 메모리 사용을 고려해 최대 4배입니다. PDF는 별도로 300 DPI로 그립니다.
- 파란색 테마를 사용합니다. 이름·날짜와 자동 생성 후보 이름은 PDF에 넣지 않습니다.

## 기존 작업을 가져올 때

기존 JSON을 불러오면 저장된 이미지의 문제 번호를 재검사합니다. 예전 HTML 자체를 계속 열면 이전 코드가 실행되므로, **v5 HTML**을 먼저 열고 JSON을 불러오세요. 이미지에 이미 누락되거나 낮은 해상도로 저장된 부분은 복원할 수 없으므로, 그 경우 원본 PDF에서 다시 추출해야 합니다. 원본에서 범위를 다시 자르려면 해당 PDF를 다시 선택하세요.

암호화되거나 손상된 PDF는 처리가 제한될 수 있습니다. PDF는 90MB, 작업 JSON은 150MB 이하를 지원합니다. 페이지 수에 고정 제한은 없지만 브라우저와 기기의 처리 한도는 있습니다. 자동 분류가 불분명한 조각은 원본과 확인하고 직접 범위를 조절할 수 있습니다.

제공된 원본 PDF로 번호와 자르기 경계를 검사하고, 회색 보기 상자·그림·긴 문제를 포함한 표본 조각은 원본과 PNG의 모든 픽셀을 비교합니다. 모든 문제의 수식 내용을 OCR로 해석하거나, 원본 스캔 자체에 없는 정보를 복원하는 기능은 아닙니다.

## 개발과 검증

앱 실행에는 npm 설치가 필요하지 않습니다. 클라우드 작업은 이미 격리되어 있으므로 기존 체크아웃을 사용하며, 명시적인 요청 없이 Git worktree를 만들지 않습니다.

```sh
cd /workspace/tutoring_helper
python3 -m http.server 8765 --bind 0.0.0.0
```

의존성과 테스트:

```sh
npm ci --ignore-scripts --cache .cache/npm
npm test
```

테스트는 시스템 `/usr/bin/chromium`, `CHROMIUM_PATH` 또는 Playwright Chromium을 사용합니다. 필요한 경우 `npx playwright install chromium`으로 브라우저를 설치할 수 있습니다. Node.js 24, Python 3.12와 Chromium에서 검증했습니다.

내장 리소스를 갱신할 때만 다음 명령을 실행합니다. 출력은 `index.html`, `vendor-manifest.json`, `THIRD_PARTY_NOTICES.txt`입니다. 잠금 파일의 정확한 버전과 무결성 검증을 사용하며, 런타임 리소스는 GZIP으로 내장합니다.

```sh
npm run bundle:vendor
```

검증은 숫자 OCR 결과 자체, 다중 문제를 포함한 구형 작업 파일 복구, 열당 실제 문제 수, 희미한 사각 테두리 픽셀 보존, 유형 제목과 노란 장 표시 제외, PDF 텍스트·점선·소프트 마스크, 인터넷 차단 상태의 실행을 포함합니다. 기존의 21쪽 PDF → 84문제 추출 → 21쪽 PDF 출력, 짧은 문제의 배율, 긴 문제를 포함한 3문제 페이지, 새 탭·작업 저장·재편집도 검사합니다. 결과물은 무시되는 `test-results/`에 저장합니다.

내장 라이브러리·언어 데이터·글꼴의 라이선스는 `THIRD_PARTY_NOTICES.txt`와 HTML 내부의 비실행 텍스트에 포함됩니다.

## 제공된 실제 PDF로 통합 검사

원본 PDF는 저장소에 포함하지 않습니다. 파일 경로를 전달해 실행합니다.

```sh
BOOK_PDF='/path/to/TalkFile_쎈 미적1.pdf' npm run test:book
```

앱에서 같은 B·C스텝만 추출할 때의 **PDF 파일 기준 페이지 범위**:

```text
5-18,23-34,41-54,59-74,79-94,97-110,115-124,129-144,147-160
```

`test-results/book-integration/`에 페이지별 경계 표시 이미지, 번호 검사 결과, 원본·앱 SHA-256, 표본 교재 PDF와 편집 가능한 JSON을 저장합니다. 표본에는 44·57·68·78·79·113·114·115번과 보기 상자, 기울어진 단 구분, 여러 장 표시 사례가 포함됩니다. 전체 812문제의 출력 배치도 열당 최대 2개·페이지당 최대 4개인지 검사합니다.
